# 0001: 使用系统 .NET Framework / WPF 和原生 HID

日期：2026-10-21

状态：已采用，限首版 Windows 11 x64。

## 背景

需求优先低后台开销、少依赖、便携运行和 Windows 11 磨砂界面，不需要跨平台、浏览器或厂商控制中心。设备电量已通过原生 HID 被动读取验证。开发机没有现代 .NET SDK，但系统提供 .NET Framework 4.8 及编译器。

## 决定

采用 C# / WPF、NotifyIcon、SetupAPI / HID 和 DWM Acrylic。不安装 SDK，不嵌入浏览器，不添加第三方运行依赖。应用只被动接收电量；主动查询保留在诊断工具，不进入常规刷新路径。

## 权衡

- 相比现代 .NET / WinUI，避免额外构建和运行依赖，便携应用较小；代价是使用较旧框架，需要自行处理托盘、材质、主题和部分控件外观。
- 相比纯 Win32 C++，WPF 更便于实现和维护现代布局；代价是明显高于纯原生窗口的内存开销。本机后台短样本工作集为 87.6 MiB，不能把小安装包等同于低内存。
- 相比 Electron / WebView，省去浏览器运行时；代价是不复用网页驱动的 WebHID 设备聚合，需要按原生顶层集合分别选择 report 7 / 6 / 8 接口。

## 后果

首版无跨平台承诺。后续以长期资源测量和用户反馈判断是否需要迁移更低开销的界面；迁移界面时保留已验证的设备映射、接口选择和状态语义，不为了将来扩展先引入插件框架。
