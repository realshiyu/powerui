## 原生 Windows 接口

同一接收器的 HID 顶层集合有独立路径。不能把网页 WebHID 的设备聚合方式直接套用到原生 API。

在已验证的 `1421` 接收器上：

| 作用 | Usage Page:Usage | Report ID | 长度（含 ID） |
| --- | --- | --- | --- |
| 电量输入 | `FF00:0002` | 7 | 19 字节 |
| 查询输出 | `FF00:000E` | 6 | 33 字节 |
| 查询 ACK | `FF00:000F` | 8 | 33 字节 |

代码同时检查 VID/PID、usage、report ID 和长度。同型号雷柏接收器通过 Windows ContainerId 关联输入和查询集合；无法唯一关联时拒绝猜测对应关系。普通键盘和鼠标输入集合不用于读取电量。

## 百分比解析

原生输入缓冲第一个字节是 report ID。对 report 7：

- 索引 7：状态，`0` 为无效，`1` 为有效电量，`2` 为充电。
- 索引 8：电量字段，仅在状态 `1` 且值在 `0..100` 内时作为新百分比。
- 状态 `2` 只更新充电状态，保留上次百分比及其原始时间，不触发低电量提醒。

WebHID 的 `event.data` 不包含 report ID，因此相应索引是 6、7，不能直接复制偏移。

托盘应用按配置间隔被动监听，每个接口最多 5 秒。多个鼠标接口并发读取，优先有效响应并保持上次选中的设备。没有有效鼠标状态时每10秒重试，系统设备变化后自动重查；没有系统事件的鼠标关机转换在下次电量查询处理。没有新报告时不猜测离线或休眠；显示 `--`，保留历史百分比和时间。雷柏接收器仍可识别型号，但 `HasStatus=false`，不更新状态时间、不触发低电量通知。

## 实验性主动查询

只有诊断程序的 `--query` 使用该路径：report 6，先用不带无线前缀的 `B0 00` 读取接收器本地固件，再使用无线前缀 `A5` 加只读鼠标固件命令 `A3 00` 或电量命令 `AA`；随后从对应集合读取 feature report 8。

本机 `1421` 固件 `0105` 的 `HidD_GetFeature` 返回缓冲从索引 `0` 开始就是 ACK，不保留请求时填入的 report ID `8`。旧实现错误地检查索引 `1`，会将 busy `2` 后的零字节当作失败，或者将固件版本当作 ACK。现在按索引 `0` 处理：`2` 重试、`1` 成功、`0` 失败。

2026-10-28 排查：用户使用 P5 PLUS 底座；本机同时枚举到 `4827` 底座和 `1421` 普通接收器。`B0 00` 稳定返回 ACK `1`，但鼠标 `A5 A3 00` 与 `A5 AA` 均为 busy `2` 后返回失败 `0`，被动监听也没有有效电量。只能确认接收器本地正常、无线鼠标查询未成功，不能据此断定是底座不兼容、鼠标断联或休眠。需结合唤醒后的读数与官方 A HUB 结果继续定位；尚未验证恢复。

P5 PLUS [官方产品页](https://rapoo.cn/product/879)说明其 USB 口可收纳鼠标接收器；不能仅因使用底座就把 `4827` 当作鼠标接收器，也不能将普通接收器的缓存无效电量当作新读数。[当前国内官方 A HUB](https://hub.rapoo.cn/) 的公开协议实现用于交叉核对上述只读命令和 ACK 语义。没有可信的 feature 响应百分比偏移，不从任意字节猜电量。常规应用仍使用被动 input report 7，不依赖主动握手。

同日直连对照：用户将接收器从底座拔出、直接连接电脑 USB 并移动鼠标后，一轮查询的接收器固件、鼠标固件、当前连接模式/配置只读查询、电量查询均返回 ACK `1`；随后收到两条 report 7，状态均为 `0`、电量字段均为 `74`。不能因查询 ACK 成功就绕过输入报告的有效性校验。后续查询再次返回鼠标 ACK `0`，仍未取得有效百分比，无法据此判定底座故障或恢复成功。

官方国内网页脚本 `https://hid.rapoo.cn/AHUB_WEB/dist/assets/js/index-3ShGzFuu.js` 中，`Nf` 将数据索引 `6`、`7` 分别解析为 `batStatus`、`batPercent`；设备列表只在 `batteryStatus != 0` 时输出百分比。这与用户反馈的官方网页有图标但无准确电量一致。状态 `0` 的数值不可提升为有效读数。诊断已增加对应说明；根本恢复仍需设备返回状态 `1` 的真实百分比或有证据支持的其他只读协议路径。

协议资料与权利边界见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。新增支持必须补充真实设备与固件的验证结果。

## 罗技 MX Master 3S / Logi Bolt

2026-10-22 实机：接收器 `046D:C548`、版本 `0503`，HID++ 长报告集合 `FF00:0002`，输入/输出 report ID `0x11`，长度均为 20 字节。电量查询仅打开厂商集合；普通输入不用于解析电量。

报告头为 `[0x11, 配对槽位, 功能索引, 函数 | software ID 0x0B]`，参数从索引 4 开始。扫描槽位 1..6，通过 ROOT 功能 `0x0000` 的 getFeature 动态发现 `0x0005`（型号）和 `0x1004`（Unified Battery）。型号长度及分段名称用于确认 `MX Master 3S`，不以接收器 PID 推断鼠标型号。

Unified Battery 函数 `0x00` 返回能力，第二参数 bit 1 必须支持百分比；函数 `0x10` 返回状态，参数 0 是百分比（0..100），参数 2 是充电状态（0 放电、1/2 充电、3 完成）。错误或未知状态不作为有效读数。不会将离散电量档位当作精确百分比。

本机动态发现槽位 2、功能索引 `0x08`，成功读取 `95%`、充电状态 `0`。索引不写死。每次刷新重新发现，单次请求最多等待 600ms，并受接口读取预算限制；优先上次槽位，第一只型号匹配且电量有效的鼠标立即返回，不必等待所有槽位。不同接收器或蓝牙接口独立读取，再按上次设备身份优先选择有效响应。

只发送型号、功能发现、电量能力和状态的只读查询，不写 DPI、按键、滚轮、配对、灯效或固件。与雷柏被动监听不同，Bolt 查询可能让设备响应，不承诺不唤醒。真实充电、睡眠、拔插与多个有效鼠标之间的切换尚待实机验证。

## 罗技 MX Master 3S / 蓝牙

2026-10-22 实机确认 `046D:B034`、版本 `0006`，厂商集合 `FF43:0202` 的输入/输出 report ID 均为 `0x11`、长度均为 20 字节。Windows 蓝牙 HID 路径使用 `VID&02046D`，不同于 USB 的 `VID_046D`；路径过滤后仍核对 HID attributes 的 VID/PID 和完整集合描述符，电量查询不直接打开普通鼠标集合。

复用上述 HID++ 型号、功能发现、能力和状态查询，蓝牙直连仅查询设备索引 `0xFF`，不扫描 Bolt 槽位。本机成功查询 `MX Master 3S`、动态功能索引 `0x08`、电量 `95%`、充电状态 `0`。面板连接类型显示为蓝牙，状态仍保存在原有 XML，设备切换时不会沿用另一设备的电量和提醒标记。

蓝牙与 Bolt 同时匹配时分别查询，优先保留上次有有效响应的接口，不猜测是否为同一只鼠标。切换设备身份或槽位后清除原设备电量及提醒标记；识别失败时不保留旧设备的实时展示。仅验证了本机蓝牙查询及面板路径；蓝牙断连重连、睡眠恢复、真实充电转换仍待验证。不将系统缓存的 GATT 电量作为新 HID++ 读数。

## 主动查询的空闲跳过

2026-11-02：托盘应用新增 `SkipIdleQueries`（默认 true）与 `IdleMinutes`（默认10，1..60分钟），鼠标与键盘各自保存。定时、设备变化和手动刷新均在发送罗技或 S99 主动查询前检查；雷柏被动读取不检查该门槛。显式主动诊断命令不受此设置限制。

通过 Windows Raw Input 后台接收设备输入，按 HID 接口路径关联 Windows ContainerId，并区分鼠标与键盘输入。只有对应容器、对应设备类型的近期活动才能允许查询，不使用全局最后输入时间。键盘只读事件头；鼠标仅判断是否有移动、按键或滚轮，活动信息只保存在内存，不记录键值或轨迹。同一 Bolt 接收器合并的鼠标输入无法进一步关联到配对槽位，门槛只能应用于该接收器的鼠标输入。

实机发现 Raw Input 的接口名使用键盘/鼠标接口类 GUID，而 HID 枚举使用 HID 类 GUID，不能直接比较完整接口字符串。比较时仅移除末尾可解析的接口类 GUID，保留完整实例、MI及Col标识并忽略大小写；本机S99三个普通输入集合去除类GUID后各自唯一匹配一个HID集合。活动时间使用单调计时，不依赖系统日期调整。

启动后没有观察到输入、ContainerId无法关联或 Raw Input 注册失败时保守跳过；不将启动、设备接入或系统恢复当作真实输入。设备移除/接入与恢复会清理活动缓存。再次收到对应类型的设备输入时，已跳过的监控器恢复刷新；跳过不更新电量时间、不触发低电量提醒，不声称设备已休眠。手动关闭开关可恢复原主动查询行为。

本地验证：应用与诊断构建通过；旧XML默认开启10分钟规则，开关关闭/37分钟保存回读、非法0分钟回退10分钟均通过；200% DPI深浅色设置截图无遮挡。S99可见但无匹配输入时确实跳过，保留原电量时间。修正接口类GUID后，真实鼠标输入2663条被识别，并取得新电量读数（80%）；该轮键盘接口不可见，尚未完成修正后S99按键恢复复核。完整10分钟静置边界及多槽位Bolt仍未实机验收，不将这些标为通过。`--capture`可用`--capture-seconds 1..900`延长诊断窗口，默认仍为8秒；诊断只输出活动计数，不输出键值或完整设备路径。
